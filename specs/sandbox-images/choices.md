# Sandbox images: implementation choices

Decisions an implementing pass made where the plan was silent. Each names the
alternative it passed over, so a correction knows what to switch to.

- **26 — The record type is `HostOperationRecord`, not `ImageOperationState`.** The store is kind-agnostic (the slice's firewall: no image logic here), and build, copy, capture and create-with-copy all land in it. Alternative: an image-named type, which would put image vocabulary into a generic owner.
- **26 — The record carries a `checkpoint` (any JSON) beside `progress`, seeded by `begin` and replaced by every `report`.** A resumer needs the kind's own resume point (a phase, a chunk bitmap) and any input the work needs, even if the daemon dies before the work's first report; `progress` (phase, completed, total) is only what callers are shown. Alternative: fold the resume point into `progress`, which would show callers a bitmap, or persist the request input separately.
- **26 — `begin(kind:key:subject:checkpoint:work:)` refuses a kind with no registered resumer.** Every journaled record must be continuable after a restart, so a kind that can start but not resume is a bug caught at the first call. Alternative: allow it and fail the record at the next start.
- **26 — An unfinished record whose kind no longer registers a resumer fails with `unsupported` at start.** No compat path for kinds a build dropped; a waiter learns it will never finish instead of polling forever. Alternative: leave it `running`, or delete it.
- **26 — `wait` returns when the work finishes or after the timeout, not on each progress change; `timeoutMs` is clamped to 0…120 000.** The caller's `{continue}` loop re-polls anyway and each answer carries the current progress; streaming phases sooner is slice 34's call if it needs it. Clamping (rather than refusing) keeps an over-long client request a normal bounded answer. Alternative: also return on a phase change, or refuse a timeout above 120 s with `invalid_input`.
- **26 — Journal timestamps are integer milliseconds since 1970 (`started_at`, `updated_at`).** ISO 8601 drops sub-second precision, so a record read back after a restart differed from the one a replay got before it; whole milliseconds round-trip exactly and match the relay's `deadline_at`. Alternative: fractional ISO 8601 with dates truncated in memory.
- **26 — Journals are never pruned in this pass.** A finished record must outlive the relay's replay window to answer a late replay, and nothing yet says how long that is. Alternative: prune finished records after a fixed age at start (left to the slice that first produces many operations).
- **26 — The daemon takes the directory as `LOCALBOX_OPERATIONS`, materialized by `install-release.sh`/`rollback-release.sh` and the proof stacks like `LOCALBOX_SANDBOXES`.** Paths reach the daemon explicitly, never derived from another path; the installer is what makes them follow `LOCALBOX_MACHINE_ROOT`. `stack up` wipes it with the sandboxes, since its keys belong to the wiped Convex account. Alternative: derive it from the sandboxes directory's parent.
- **26 — The daemon resumes operations after `host.recover()`.** A resumed capture or create-with-copy may act on a sandbox, which must be back first. Alternative: resume before the socket opens.
