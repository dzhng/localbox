- Slice 00 keeps relocated credentials inside LOCALBOX_MACHINE_ROOT while the default credentials file remains ~/.config/localbox/credentials.json.
- Slice 00: local Convex runs in `CONVEX_AGENT_MODE=anonymous` (the Convex CLI 1.42 removed `--local`, and anonymous local deployments can't be created with `deployment create`). The stack waits for "Convex functions ready" rather than trusting a stale `.env.local`.
- Slice 00: stack children write straight to their log files (detached, no pipes) so `stack up` returns while the stack keeps running.
- Slice 00: the runner discovers probes by their `NN-` prefix, runs `all` and `--through NN`, prints one verdict line per slice, and treats a run as blocked (exit 2) only when every failure starts with `blocked:`. Probes get `exec` and `stack` helpers on the context.
- Slice 00: the daemon's env names became `LOCALBOX_SOCKET` and `LOCALBOX_IPC_TOKEN_PATH` (explicit paths handed over by the installer); the CLI's Keychain storage was removed here rather than in slice 06, since the credential path moved to `machinePaths()`.
- Slice 05 (D3): typed Convex modules use `service:*` and `machine:*` function ownership, with machine revocation checked on every authenticated call; ES256 tokens are signed directly with Node crypto and local JWKS is embedded as a data URI.
- Slice 05: the legacy relay functions that took a machine identity (`requests.get/claim/recordResponse/ack`, `channels.get/validate`) are service-only until slice 07 replaces them; as written they let one account's machine claim another account's requests. The only machine-callable function is `machines:self`, which returns the caller's own record.
- Slice 05: `snapshots:get` and `admin:wipe` are internal functions reachable only through `npx convex run`; `scripts/convex-wipe.ts` uses that route. Last-seen is not written on every call (it belongs to the machine-token route in slice 07).
- Slice 05: tokens carry `kid` = the RFC 7638 thumbprint of the signing key; `packages/tokens` owns both signing and the JWKS document (`publicJwks`, `scripts/jwks.ts`), so the two can't drift. Convex rejects tokens without a `kid`.
- Slice 05: the proof stack generates a dev key under `.localbox/proof/keys`, starts Convex, sets `LOCALBOX_JWKS` and `LOCALBOX_API_ORIGIN` after the backend is up (the auth config can't push before they exist) and retries the start when the Convex CLI's version check fails.
- Slice 05: the list of public Convex functions lives in `tests/fixtures/convex-public-functions.ts`; a test asserts it matches the exported functions exactly, and both the unit test and the proof probe use it.
- Slice 06: the relay authenticates machine secrets through a service call, then mints a short-lived machine JWT for account catalog operations; secrets never leave Convex in stored form.
- Slice 06: sign-in codes come from `crypto.getRandomValues` with rejection sampling (the first version used `Math.random`); machine credentials are looked up through a `by_credential_hash` index instead of a table scan.
- Slice 06: the relay entry creates a Convex client per call. Function instances serve concurrent requests and auth is per client, so a shared client could run one machine's request with another's token.
- Slice 06: a rate-limited verify answers 429. The account-executor operation table currently lives inline in `apps/relay/api/[...path].ts`; slice 07 moves the agent API (`/api/v1/ops`) into its own module when it adds machine-bound operations.
- Slice 06: `stack up` wipes the local anonymous Convex once it's ready, because that backend keeps data (including per-IP limits) between runs.
